快速开始

扩展有两种用途：等待已有实例所在主机释放 GPU，或在源实例同地区寻找其他主机，自动克隆数据并开机。

  1. 在安装扩展的同一个浏览器中登录 AutoDL 控制台。
  2. 想换主机找卡：源实例关机后，从“更多 → 克隆实例”进入，勾选数据盘并继续，打开扩展的“自动克隆”。
  3. 只想开启原来的实例：留在实例列表，打开扩展的“原实例开机”，选择要监控的实例。
  4. 按需配置“通知设置”，然后开始监控。自动克隆启动后会滚动到顶部显示状态。
  5. 保持电脑、浏览器和 AutoDL 标签页运行。成功后在控制台检查实例、数据及费用。

点击“开始监控并自动创建”，即允许扩展在设定条件内创建并开机一个付费实例。停止监控不能撤回已经提交的创建请求。

安装与更新

首次安装

  1. 从 项目仓库的 main 分支下载代码并解压，或使用 Git 下载。
  2. Edge 地址栏输入 edge://extensions/；Chrome 输入 chrome://extensions/。
  3. 开启“开发人员模式”，点击“加载解压缩的扩展”，选择直接包含 manifest.json 的文件夹，不要选它的上一级。
  4. 将扩展固定到工具栏，方便打开。加载使用不需要 Python、Playwright、Node.js，也不需要安装测试依赖。

更新已有安装

  1. 先停止监控；若任务已经提交或结果不明，先查看 AutoDL 控制台。
  2. 将同一个扩展目录中的文件更新为最新版本。通过“加载解压缩的扩展”安装的版本不会自动从 GitHub 更新。
  3. 在扩展管理页点击该扩展的“重新加载”。如果浏览器要求确认新增站点权限，完成确认。
  4. 刷新已打开的 AutoDL 页面，使网页脚本同步更新，再重新设置监控。

优先更新原目录并重新加载，通常能保留设置和日志。不要同时启用两份扩展；改用另一目录或移除扩展可能导致配置不再沿用。

选择监控方式

方式会做什么适合什么情况
自动克隆在源实例同地区寻找符合条件的其他主机，复制系统盘和数据盘，创建并开机一个新实例。原主机长期没卡，接受换主机，想继续使用源环境和数据。
原实例开机监控所选已有实例，在所在主机有可用 GPU 时开机；无卡运行的实例可能被关机后重新带卡启动。希望保留原实例、原主机，或不想复制数据。

两种方式共用通知配置。当前版本会阻止两种监控同时运行；克隆任务结果不明时也会阻止启动原实例监控。切换顶部菜单只是换界面，不等于停止任务。

原实例模式支持多选，所选实例可能依次全部开机并计费。如果只想获得一台可用实例，只选一个。自动克隆每次任务只提交一个新实例。

自动克隆

1. 从正确的源实例进入

  1. 在 AutoDL 控制台找到要复制的源实例，确认实例及其数据正确，并先关机。
  2. 点击该实例的“更多 → 克隆实例”。在弹窗中勾选数据盘，然后点“继续”。
  3. 进入克隆选机页面后，先不要手动点“创建并开机”。打开扩展，切到“自动克隆”，点击“读取当前克隆页”。
  4. 核对扩展显示的源实例 ID 和地区。读取失败时，不要换成普通的“租用新实例”页面，重新从源实例进入克隆。

扩展只接受源实例同地区的克隆，系统盘和数据盘都要复制。源实例仍然保留，不会被插件自动释放。原实例的保留、存储等费用以 AutoDL 为准。

2. 设置筛选条件

参数填写方法
GPU 型号至少选一种。Windows 按住 Ctrl 点击可多选。多选表示任一种型号都能接受，不是按选择顺序排优先级。型号精确匹配，例如 RTX 4090 与 RTX 4090D 不视为相同。
GPU 数量创建一台实例需要的卡数，选项为 1–8、10、12。要求同一台主机有足够空闲卡，不会把不同主机的卡拼起来。
整台实例价格上限单位为元/小时，填写大于 0、最多两位小数的金额。是所有卡的合计小时价，不是单卡价。例如单卡 1.98 元，两卡合计 3.96 元，上限填 3.00 就不会选择它。
数据盘额外扩容单位 GB，非负整数。扩容 50 GB 填 50，不是填总容量；不扩容填 0。不能低于源实例已有扩容量。主机的“可扩容”必须严格大于填写值，例如填 50 时，容量等于或小于 50 的主机都会跳过。
检查间隔3–3600 秒整数。它是每轮结束后的等待时间，网站加载和扫描还会增加耗时；3 秒不等于保证每 3 秒完成一轮。网络慢时可设 5–10 秒。

只支持按量计费。价格核对读取页面的“配置费用（元/时）”，不把“日常费用（元/日）”或余额当作小时价。小时价上限不代表总支出上限，开机多久、存储费用及最终账单仍需要自己管理。

1.1.8 支持按用户填写的大小扩容数据盘：先检查主机容量，选中主机后才勾选“需要扩容”、填写数值并核对。未选中主机时页面容量范围可能是 0，此时扩展不会填写。

扩容按页面的日常费用单独按日收费，不计入 GPU 小时价上限，关机后仍可能继续扣费。点击开始即授权按填写大小扩容。提交前会再次确认勾选状态、实际填写量、主机容量和日常费用，变化时不会按旧值提交。扩容大小与费用也会记入日志。

1.1.7 会读取克隆页参数中的镜像 CUDA 版本，跳过页面标注最高 CUDA 版本更低的主机。版本信息缺失时仍依赖网站原生校验；不会修改源实例环境或换镜像。

3. 开始监控

点击“开始监控并自动创建”。顶部显示当前状态、已检查轮数和下一轮等待时间。每轮通过切换一个选中的 GPU 筛选项来刷新 AutoDL 主机列表，并检查库存、型号、卡数和价格。

运行期间不要手动更换地区、源实例、计费方式、筛选条件或提交创建。需要修改条件时先停止，重新设置后再开始。

4. 创建与核实结果

找到合格主机后，扩展选中它并核对最终小时价，再提交一次创建。提交后会短暂打开后台实例列表标签页来核实结果，读完自动关闭。通常约每 30 秒核实一次；数据复制耗时不包含在检查间隔内。

只有唯一匹配的新实例已经带 GPU 运行，才判定成功并发送成功通知。跟踪期间不要在同一目标主机手动创建相同规格实例，以免无法区分。

提交结果不明或长时间未完成时，插件会保留提交锁，避免重复创建。额外确认弹窗可能需要人工处理。看到页面错误或“卡被占用”后，先看插件状态和实例列表，不要连续点击创建。

原实例开机

  1. 打开 AutoDL 的“容器实例”列表并保持登录。
  2. 扩展切到“原实例开机”，点击“刷新实例列表”。
  3. 选择目标实例；按住 Ctrl 可以多选。核对名称，不要选中正在运行重要任务的实例。
  4. 选择检查间隔：3、5、10、15、30 或 60 秒，默认 5 秒。
  5. 点击“开始监控”，确认状态显示已开启。

已关机的实例在有 GPU 时会尝试开机。处于“无卡模式运行”的实例在有卡时可能被关机、再带 GPU 开机，因此其中正在执行的 CPU 任务也可能中断。

每成功处理一个实例就将其移出监控列表，直到所有选中实例完成后停止。手动停止可阻止后续检查，但已经发出的开关机请求仍需要在控制台核对。

状态、停止与提交锁

看到的状态含义与操作
正在检查 / 等待下一轮监控已开启；暂时没找到符合条件的库存会继续等待。轮数在一轮扫描完成后增加，不会一启动就增加。
正在提交 / 核实新实例创建已进入提交流程。等待结果，检查是否存在需要人工确认的弹窗。
已成功已确认新实例带 GPU 运行。检查新实例的系统环境、数据盘和计费，再开始工作。
出错 / 结果不明先读完整状态说明，再检查控制台和日志。不要把“没有立刻看到新实例”当作一定没有创建。
已停止后续监控停止。它不会释放实例、关掉已成功的新实例，也不会撤销已经提交的操作。

需要解除锁定时，先确认控制台里是否存在新建、创建中或运行中的实例，以及是否有尚未完成的请求。确认后再点击“已核实控制台，解除提交锁定”。这个按钮只解除本地锁定，不会取消远端任务。

提交前发现库存被抢或报价变化，可以继续监控。提交后如果网站明确提示“GPU库存发生变更，请刷新后重新选择”，会刷新库存继续寻找，并暂避刚失败的主机 30 秒；新的尝试会重新核对库存和报价。

如果原生弹窗明确提示镜像 CUDA 高于主机支持版本、无法开机，插件只点击“重新选择”，待弹窗关闭后跳过该主机继续寻找。其他未知提示不会触发自动重试，提示文字会进入日志，结果不明时先核实控制台。

微信测试号通知

适合个人自用和开发测试。扩展直接请求微信官方接口，不需要额外服务器，也不需要电脑微信客户端保持登录。不经过 Server酱，所以不受 Server酱免费版每天 5 条限制；仍有微信自己的额度、权限和测试用途规则，以后台为准。

1. 登录并关注测试号

  1. 打开 微信官方测试号后台，用个人微信扫码登录。
  2. 找到测试号信息中的 AppID 和 AppSecret。不要将 AppSecret 发给别人或放到公开截图中。
  3. 用需要收通知的微信扫描后台的测试号二维码并关注。在关注用户列表中复制这个用户的 OpenID。OpenID 不是微信号，也不是昵称。

2. 创建六行消息模板

新增测试模板，标题填“AutoDL 通知”，完整复制以下内容，花括号、字段名和 DATA 大小写都保持一致：

通知：{{title.DATA}}
内容：{{content.DATA}}
主机：{{host.DATA}}
实例：{{instance.DATA}}
配置：{{spec.DATA}}
时间：{{time.DATA}}

保存后复制生成的模板 ID。已有旧三行模板的用户，请新建为这份六行模板，再替换插件里的模板 ID；仅更新扩展不会改变微信后台的模板。

3. 在扩展里保存并测试

  1. 打开“通知设置”，勾选“微信测试号通知”。
  2. 分别填入 AppID、AppSecret、接收用户 OpenID、模板 ID。
  3. 点击输入框外会自动保存；点击“发送测试通知”也会先保存当前填写内容。
  4. 检查手机实际收信，确认通知、主机、实例、配置、时间均有显示。测试中的主机与配置只是示例，不代表真的创建了实例。

“微信接口已接受”表示接口返回成功，不保证手机已弹窗或已读。若收不到，请先检查关注用户、通知开关和手机系统设置。一般不需要配置测试号的消息接收服务器 URL/Token，因为扩展只主动发消息，不接收回调。

为什么内容被省略，或没有“详情”？

微信可能将过长的单个字段省略，不能靠换行强制展开。新版用简短状态，并将主机、实例 ID、配置独立展示；特别长的字段仍可能被省略。当前不提供独立的详情网页，也不设置跳转到 AutoDL。旧消息已有的跳转链接不会被更新修改。

原实例模式未提供某些字段时会显示“未提供”。提醒声音、锁屏展示和勿扰规则由微信与手机控制，插件不能强制让手机响铃。

常见接口错误

错误码处理方法
40013 / 40125核对 AppID / AppSecret，确认都属于同一个测试号。
40003OpenID 无效；从当前测试号关注用户列表重新复制。
40037模板 ID 无效；确认模板属于当前测试号。
43004接收用户未关注测试号，先关注。
40164按后台要求配置当前电脑的公网出口 IP 白名单；切换网络后可能需要更新。
45009 / 48001达到微信接口额度 / 缺少接口权限，查看后台配额和权限表。
网络失败 / 超时检查网络。超时可能已被微信接受，先查手机；插件不会自动重发此类请求。

Server酱与邮箱通知

通知设置由两种监控共用。可只启用一种，也可以同时启用多个通道；多个通道会分别发送，可能收到重复提醒。通知发送失败不代表开机失败，请以控制台和监控状态为准。

Server酱

  1. 到 Server酱官网扫码登录，在其后台绑定接收通道，先用网站的测试功能确认收信。
  2. 复制 SCT 开头的 SendKey；插件当前使用的是 Turbo 接口，不支持直接填其他版本的地址。
  3. 在扩展“通知设置”中勾选 Server酱通知，填写 SendKey，点击输入框外保存。

Server酱负责转发，设置相对简单。免费版每天最多 5 条，实际额度及套餐规则以其官网为准。它的 SendKey 与微信测试号的 AppSecret 是两种不同配置，不要互填。

EmailJS 邮箱

  1. 在 EmailJS 注册，添加可发送邮件的服务并创建模板。额度、账户限制和接口访问设置以 EmailJS 后台为准。
  2. 模板收件人使用 {{to_email}}，主题使用 {{subject}}，正文使用 {{message}}。
  3. 从后台获取 Public Key、Service ID、Template ID；在扩展勾选邮箱通知，填入这三项和实际收件邮箱，点击输入框外保存。
  4. 先在 EmailJS 后台验证服务和模板可发信。插件当前只有微信测试号的独立测试按钮；邮箱通道在成功开机后发送。

不需要在代码里填写密钥、不需要修改扩展安全策略，也不需要下载外部 SDK。收不到邮件时检查垃圾箱、服务授权、模板变量和后台发送记录。

“清除通知配置”会同时删除微信测试号、Server酱和 EmailJS 的配置。只想暂停某个通道，取消其勾选即可。

诊断日志

扩展弹窗底部展开“诊断日志”，可以查看记录数量与占用、导出文件或清空。日志只保存在本机，最多 512 KiB 或 1000 条，先达到哪个就按哪个限制淘汰最旧记录。重新加载扩展或重启浏览器后仍保留。

主要记录克隆任务的状态、轮数、脚本版本、候选库存和报价比较，以及微信测试号通知的接口结果。它不是 AutoDL 全部操作的审计记录，也不会补录旧版没有保存的历史过程。

  1. 遇到问题先保留页面和状态，展开“诊断日志”，点击“导出日志”。
  2. 保存浏览器下载的 autodl-diagnostics-时间.jsonl 文件。
  3. 反馈时附上文件、实际操作步骤、期望结果及出错时间；页面截图可补充现场提示，注意遮住密钥和密码。

日志包含版本、时间、状态及最近克隆任务摘要。报价错误时可看到小时配置价、单卡价、卡数、计算总价和上限。导出、清空都不改变任务或解除提交锁。

1.1.7 同时记录右上角通知和页面弹窗中的未知提示、出现时间、对应主机及提交尝试标识，并记录实例列表核实结果。单条提示最多保存 4000 字符，保留换行、敏感文本仍会脱敏；总量限制不变。

日志不自动上传，不记录 Cookie、SSH 密码、页面 HTML 或通知密钥，并对常见敏感文本做脱敏。实例 ID、地区等排查信息仍可能存在，发送前可以自行检查。

常见问题

关闭扩展弹窗后还会运行吗？
不需要一直打开弹窗。浏览器和对应 AutoDL 标签页需要保持运行，电脑不能休眠；关闭弹窗也不等于停止任务。
需要一直让 AutoDL 标签页在最前面吗？
可以切换标签页，但后台标签页可能被浏览器限速、休眠或丢弃。将 AutoDL 加入 Edge 不休眠站点，并保持电脑唤醒，实际刷新周期仍取决于浏览器和网站。
重启浏览器后是否自动恢复？
设置、日志和克隆任务状态可以保留，但不要假定监控必然持续恢复。重新打开 AutoDL、确认登录及控制台，再检查扩展状态。已提交或结果不明的任务先核实，避免重复创建。
页面提示版本不一致，或更新后界面仍是旧版？
确认扩展管理页加载的是最新文件所在目录，重新加载扩展，再刷新 AutoDL 页面。只更新 GitHub 文件或只重开弹窗，都不能替换网页中已运行的旧脚本。
有库存却没有选中？
核对型号是否精确匹配、同一主机空闲卡数是否足够、主机是否可选、所有卡合计小时价是否在上限内，以及源地区是否正确。全站有卡不代表源地区有卡。
报价核对失败怎么办？
先查看状态中显示的实际配置小时价、单卡价、卡数和上限。不要把日常费用或单卡价当成总价。确认参数无误后导出日志，网站报价结构变化也可能导致停止。
源实例扩容了 50 GB，要填多少？
在扩展的“数据盘额外扩容”填 50，或你确定需要的更大整数值；不能填数据盘总容量，也不能填小于源扩容量的数值。插件会等待既有卡、又有足够扩容空间的同地区主机。
检查轮数为什么暂时不动？
完成一轮才计数。页面正在加载、扫描或创建跟踪时可能不增加；长时间没有进展时查看状态说明、登录状态和日志。
卡被别人抢了，会继续吗？
会识别“GPU库存发生变更，请刷新后重新选择”这一明确提示，结束本次失败尝试、暂避该主机 30 秒并刷新继续找卡。其他未知提示只记录到日志并保留锁定，避免重复创建。
换电脑或用 ZIP 安装会影响创建吗？
扩展不依赖原电脑的运行环境，可以打包移动。只需加载正确的完整目录，在新浏览器登录 AutoDL，并刷新页面。浏览器保存的设置、日志和提交状态不会因为复制源码 ZIP 自动迁移，需要重新配置；排查时以日志里的弹窗、后台、网页脚本版本为准。
克隆成功后源实例会被删掉吗？
不会，源实例保留。请自己确认新实例数据和环境正常，再决定怎样处理源实例以及后续费用。
能保证一定抢到卡吗？
不能。库存会被其他用户同时竞争，页面和网络也有延迟；缩短间隔不能消除这些因素。
